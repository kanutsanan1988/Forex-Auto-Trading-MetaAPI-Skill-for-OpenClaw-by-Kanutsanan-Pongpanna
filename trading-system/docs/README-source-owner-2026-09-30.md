## 0. โหมดการเทรด — ผู้ใช้เลือกเองตอนเริ่มใช้งาน (2 โหมด)

**นิยามบทบาท AI:** “Hermes” คือชื่อเรียกบทบาท Agent หลักที่ประสานงานกับระบบ ไม่ได้ผูกกับยี่ห้อหรือแอปใด ตอนนี้ผู้ช่วย Codex ในงานนี้ทำหน้าที่ดังกล่าวได้ และในสำเนาแจกจ่าย Agent หลักของแพลตฟอร์มที่ผู้ใช้เลือกก็ทำแทนได้ ส่วนคำสั่ง Hermes CLI/cron ที่ระบุในรายละเอียดด้านล่างเป็น adapter ของเครื่องต้นทาง ไม่ใช่ข้อกำหนดของแพลตฟอร์มปลายทาง

Agent หลักตัวเดียวกันรับงานได้ทั้งบทบาทประสานงาน, บอทสัญญาณโหมด 2 และ Admin Bot โดยทำตาม brief และสิทธิ์ของแต่ละงาน ไม่จำเป็นต้องมี Agent สามตัวหรือใช้ผลิตภัณฑ์ Hermes แยกต่างหาก

**Jev เป็นส่วนเสริมที่เลือกได้:** เครื่องต้นทางตัวอย่างใช้ OpenRouter เชื่อม Jev; ผู้ใช้สำเนาแจกจ่ายจะใช้ provider/adapter อื่นที่ตนจัดทำ หรือไม่ใช้ Jev เลยก็ได้ ปัจจุบัน source นี้มี OpenRouter transport เป็นตัวอย่าง ยังไม่ใช่ชุด adapter หลาย provider ที่พร้อมใช้ทันที เมื่อ Jev ถูกปิด, ไม่มี credential, เชื่อมต่อไม่ได้ หรือคำตอบผิดรูป ผู้เรียกต้องรับสถานะ unavailable และทำงานต่อโดยไม่ใช้ Jev; การไม่มี Jev ไม่ควรหยุด Python trading/research หรือสร้างสัญญาณเทียม

| โหมด | ทำงานอย่างไร | งานอัตโนมัติที่เปิด |
|---|---|---|
| **1. เทรดด้วยสัญญาณภายใน** | ระบบเทรด + งานวิจัย + ตัวปรับ Python ทั้งหมด; ไม่ใช้ AI/LLM ที่เชื่อมกับระบบ | งาน Python ภายในยังทำงาน; AI integrations ต้องถูกปิด/กันด้วย mode gate |
| **2. เทรดร่วมสัญญาณ AI** ← **ค่าเริ่มต้น** | ระบบ Python เหมือนโหมด 1 ทุกส่วน และอนุญาตให้ AI/LLM ทุกส่วนที่เชื่อมกับระบบทำงาน ไม่จำกัดเพียง Signal Bot กับ Admin Bot | AI jobs และ AI callsites ที่ลงทะเบียนไว้ โดยแต่ละ provider ยังเคารพสวิตช์เปิด/ปิดของตนเอง |

**วิธีเลือกตอนเริ่มเทรด**
1. ดับเบิลคลิก `start_FULL_system.cmd` → ถ้ายังไม่เคยเลือก ระบบจะ **เด้งเมนูเลือกโหมดให้อัตโนมัติ** (ครั้งแรกเท่านั้น)
2. พิมพ์ `1` หรือ `2` แล้ว Enter; **Enter เปล่าที่เมนู = โหมด 2**; `0` ยกเลิก เมื่อเปิดระบบโดยมีโหมดบันทึกอยู่แล้ว ระบบคงโหมดนั้น
3. เปลี่ยนโหมดภายหลังได้ทุกเมื่อ: ดับเบิลคลิก `choose_mode.cmd` — **มีผลทันที ไม่ต้องรีสตาร์ท**

> ทั้งสองโหมดยังได้ **การปรับ 36 ค่า + เกณฑ์การสร้าง TP/SL อัตโนมัติ** จากระบบภายใน Python — โหมด 1 ปิด/กัน AI; โหมด 2 เปิดสิทธิ์ให้ AI ที่เชื่อมอยู่ แต่ไม่เปิด provider ที่ผู้ใช้ปิดไว้ และไม่เปลี่ยนสิทธิ์ Live
> รายละเอียด/กลไก/pitfalls: `research/2026-09-13-trading-modes-internal-vs-llm.md`

รายละเอียดในบันทึกวิจัยเก่าเป็นประวัติ ไม่ใช่ข้อกำหนดปัจจุบัน โหมดไม่ได้หมายถึงปิด/เปิดงานวิจัยทั้งหมด และไม่ได้กำหนดสัดส่วนรวมสัญญาณ 50:50 ตายตัว บอทส่งคำแนะนำผ่าน `tools/submit_recommendation.py` ส่วน Python ส่งผ่านเส้นทางภายใน; ทั้งคู่ใช้กล่อง `research/recommendations/latest_recommendation.json` เดียวกัน

**ค่าเริ่มต้นไม่ใช่คำสั่งเปิด Live:** การเลือกโหมดไม่เพิ่มสิทธิ์ Live ไม่ลบ Kill Switch ไม่ส่งออเดอร์ และไม่เปิดงานขณะ STOP อยู่ โหมด 2 ต้องตั้งค่าบอท/ผู้ให้บริการและตรวจค่าใช้จ่ายก่อนใช้งาน; ถ้ายังไม่พร้อม ผู้ใช้เลือกโหมด 1 ได้

> - **ร่องรอยที่ต้องระวัง**: ชื่อระบบมีคำว่า "AI(LLM) Live Research" และบันทึกมี event `dual_agent_result`
>   ซึ่งเป็นของ**ชั้นวิจัย/ชั้นบน** ไม่ได้แปลว่าตัวเทรดต้องใช้ AI — ตัวเทรดเรียกได้แต่ต้องถอยกลับไปใช้ Python ได้เสมอ
> AI อยู่ใน **ชั้นบน 3 ชั้น** เท่านั้น: ① ชั้นการปรับตัว (งานวิจัย) ② ชั้นวิวัฒนาการ (แอดมินบอท) ③ ชั้นที่ปรึกษา (Hermes = สมองหลัก)

|---|---|---|---|---|

| breakout_reversal | [0.60, 0.90] | [0.60, 0.90] | 0.60 | 1.00 |

- **ranking_priority = weight** (เลือกอัตโนมัติจาก **net expectancy ต่อ trade** — v0.11)
- ★ **NET-PROFIT FIRST**: auto_threshold ตัดสินด้วย **net expectancy (USD/trade หลัง spread/commission)**
  — net เฉลี่ย < 0 → กรองเข้ม / net เฉลี่ย > เป้า → ผ่อนรับ (winrate เป็นแค่ข้อมูลรายงาน
  เพราะ winrate สูงแต่ R:R แย่ก็ขาดทุนได้)
- ★ **FREQUENCY FLOOR (ห้ามปิดกั้นการเทรด)**: เงียบไม่มีออเดอร์ ≥ 12 ชม. → ผ่อน band อัตโนมัติ;
  ออเดอร์รวมน้อย → ห้าม tighten (LOOSE_SKIP_LOW_FREQ); lockout 24 ชม. → กลับ baseline
- หลักเกณฑ์: raw = band (reversal-risk), prob = threshold(กัน overfit), weight = multiplier
- auto_threshold: p60/p90 + **net expectancy (ตัวตัดสินหลัก)** + band_health + FREQUENCY FLOOR (lockout 24ชม. → relax)

**กฎกันปิดกั้นการเทรด (FREQUENCY FLOOR):**
- เงียบไม่มีออเดอร์ ≥ 12 ชม. → ผ่อน band อัตโนมัติ (1 ขั้น)

- เงียบ ≥ 24 ชม. (lockout) → คืนค่า baseline ทั้งชุด
- adaptive gate: ปิดกลยุทธ์พร้อมกันได้ **ไม่เกิน 2 ตัว** และปิดนาน ≥ 12 ชม. → **เปิดคืนอัตโนมัติ** (audit: adaptive_reenable)

- profit-anchor restore: คืนค่าแล้ว **เปิดทุกกลยุทธ์เสมอ** (trade_enabled=true)
- exit / TP / hedge / risk ไม่ถูกแตะโดยการปรับ band (ไม่มีทางล็อกการเทรดจากทางอื่น)
- ทดสอบกลไกนี้: `test_freq_floor.py` (11 เคส — ผ่านทั้งหมด)

**วงจรปิด:** สังเกต (research-analytics) → วิเคราะห์ net → เสนอ REC → ทดสอบ (gate) → apply → hot reload
→ สังเกตใหม่ → ปรับต่อ — ทำงานตลอดเวลา ไม่ต้องรอคนสั่ง

### 12.2 เส้นทางของไม้ 1 ไม้ (ลำดับด่าน)
```
ตลาดเปิด (market_clock)
  → สัญญาณ M1 (strategy_engine: 6 กลยุทธ์ × Buy/Sell)
  → ★ ด่าน 1 · ประตู NET      ดูไม้ที่ปิดภายใน 12 ชม. ฝั่งนั้นต้อง net ≥ 0
  → ★ ด่าน 2 · ประตู 36 ค่า    raw / probability / weighted ต้องผ่าน band ที่ปรับเอง
  → ★ ด่าน 3 · เทียบสองฝั่ง    ถ้าฝั่งตรงข้ามของกลยุทธ์เดิมน่าสนใจกว่าและผ่าน 36 ค่า
                               → พลิกเทรดฝั่งตรงข้าม (ไม่ต้องผ่านประตู net)
                               → ถ้าไม่ผ่าน = ไม่เทรด (abstain)
  → คำนวณขนาดไม้ + SL (ATR × 1.2) + TP (R:R ขั้นต่ำ 1.3)
  → เปิดไม้จริง (ตรวจ spread · revenge_guard · cooldown)
  → ติดตามทุก 60 วิ → ticker ปิดไม้ (TP / SL / early_cut / profit_exit)
  → กลับไปเช็คเทรดใหม่ทันที
```

### 12.3 กลไกที่ทำงานอัตโนมัติ (กันพลาด + ปรับตัว)
| กลไก | ค่าที่ตั้ง | หน้าที่ |
|---|---|---|

| กันแก้แค้น | 15 นาที · คะแนนแรงกว่า +0.05 | ห้ามเข้าซ้ำฝั่งที่เพิ่งแพ้ |
